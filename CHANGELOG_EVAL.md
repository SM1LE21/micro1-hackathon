# Improvement changelog

The story of how the solution evolved, in the official format. One entry per meaningful experiment, measured with the same evaluation wherever possible. Removed experiments stay in — they taught us something.

| Stage | What you tried and why | Evidence | Decision / learning |
|---|---|---|---|
| Baseline — 2026-08-31 15:10 UTC | The same model through the author's Claude Code login (`claude-opus-5`, `--brain claude`), the instruction bytes both arms share (`art30/prompts/system.md`), three read-only tools, five `submit_record` attempts checked for schema validity and nothing else, no verifier, no gate (`baseline/arm.py`; ADR 0003 §4). Dev split S01–S07, three runs per case, `--jobs 1` | dev F1 0.86 ± 0.07; false safe 0; pass 9/21 runs; $0.34 per run at list prices; 20 + 1 = 21. Trace read: `traces/baseline/S01-s3.jsonl` — the first submit carried no record object, the second had the record nested under a second `record` key, the third was accepted; three attempts, 80 s and $0.41 against 48 s and $0.27 for its two siblings | Starting point. Where it lost F1: S04, 0.75 on all three seeds, is a name and not a verdict — the record calls the object store `uploads/avatars` (the S3 prefix) where the manifest says `uploads`, the scorer normalises them to different keys, and the same tuple appears once as `missing` and once as `spurious` while `verdict_confusion` is `erased → erased` (`results/runs/baseline/S04/s1/metrics.json`). The advanced arm loses it the same way on two of three seeds. `norm()` is frozen with the metric (`evals/harness/score.py`), so this stays a known artefact of the eval rather than a fix made after the runs |
| Iteration 1 — the closed loop | `submit_record` closed over the verifier: schema, the ten handler invariants, then call-graph reachability from every erasure entry point to a deletion primitive, per store (`art30/verify/`, `advanced/arm.py`). A struck claim returns as the tool result with the reason and the line; an unresolvable call renders `unverified`; the gate approves by construction in scored runs (`--approve auto`). Same prompt bytes, same tools, same five attempts | dev F1 0.90 ± 0.06 against 0.86; paired bootstrap Δ +0.034, 95% CI [-0.007, +0.085]; McNemar b=0 c=0 p=1.0000; false safe 0 → 0; $0.34 → $0.37 per run; regressions n/a (first sweep). Refusals in the 21 advanced dev runs: 9, in 6 runs (`run_end.verify_rounds` of `traces/advanced/S04-s2`, `S04-s3`, `S05-s1`, `S05-s3`, `S06-s1`, `S07-s2`) — first-attempt schema shapes, two admin entry points the model had not declared (S06), and citations one line off (S05, S06); not one call-graph verdict was struck on dev. Trace read: `traces/advanced/S06-s1.jsonl` — attempt 1 refused on four schema errors, attempt 2 on `admin_delete_model`/`admin_delete_selected` missing from the entry points and one bad citation, attempt 3 on two citations, attempt 4 accepted with every verdict as in attempt 2 | On dev the closed loop buys +0.03 F1 with a bootstrap interval that touches zero, one failure fewer (the baseline's `S05-s1` died at render on a citation one line off — `cache.py:16` for `purge_session`, defined at line 15 — the same error the verifier hands back as `bad_citations` in the advanced arm and the model fixes in one more attempt), and 7 → 3 reaching claims on stores the manifest does not name. The verdicts themselves this model got right in the open loop; what the verifier corrected was everything around them |
| Incident 2026-08-31 14:44 UTC | First dev+test sweeps on the claude brain: all 60 cells died in 0.2 s | Traces of the failed sweep cleared; ledger line 1 in `results/test-runs.log` records the spent slot | The driver handed the CLI a relative `mcp.json` path that the child resolved against the scanned repository. Fixed (`art30/brains/driver.py` resolves every child-facing path), regression-tested, sweeps re-run. A harness defect, not a model result; kept here so the ledger's first line has its explanation |
| Incident 2026-08-31 15:25 UTC | `make smoke` runs `trace_check` over the committed traces; on `traces/baseline/S01-s3.jsonl` check 9 failed: `run_end.verify_rounds` 1 against 2 refused submits on the step lines | Commit da891dc; `uv run python -m evals.harness.trace_check traces/` clean afterwards | The driver summed `verify_rounds` from the spool, which never sees a refusal the MCP server makes before the arm's handler runs (`arguments must carry a record object`). Now counted off the step lines, as the checker does; the one trace's `run_end` was re-derived from its own lines and no step line was touched. Both harness defects of the day were caught by the harness's own checks, neither by reading a record |
| Removed — real repositories as scored cases | R01–R04 vendored at pinned SHAs on day one so the eval would not be synthetic only (`evals/fixtures/real/`, `evals/CASES.md` §Real cases); ground truth to be hand-labelled under the CASES.md protocol with the timer running, before any run | No `evals/fixtures/manifests/R0*.yaml` exists; commit 7521862 drops them from the scored set; `evals/split.yaml` still lists them; the demo repos D01/D02 took their place for hand testing | Never labelled: the hours budgeted for labelling went to the verifier and the brains. An eval case is its label, not its repository; without one a real repo is a demo and runs as one (`docs/cli.md`). The human-time row of the results table went with it — unmeasured, so cut rather than estimated |
| Removed — the API path as the scoring engine | ADR 0005 planned every sweep on `--brain api` at `--jobs 4` under a $300 ceiling, with responses recorded for `make eval-replay` | `results/metrics.json`: `brain: claude`, `cost_source: cli_estimate`; `results/test-runs.log` reason field `brain claude`; no `evals/cache/` | No credits were spent: ADR 0008 built the login brain and the sweeps ran on it at `--jobs 1` in one window. Three things moved with it and every table labels them: cost is an estimate at list prices from the CLI's token counts, arm identity is checked on `prompt_sha` rather than the request hash, and reproduction is `make eval-replay-local` (re-verify, re-score, diff) because no response exists to replay |
| Final — test split, 2026-08-31 | S08–S10, both arms, three runs each, one window, ledger line 2, on the code as frozen | test F1 0.88 ± 0.04 → 0.86 ± 0.03; false safe 0 → 0; McNemar b=0 c=0 p=1.0000 (three cases: the smallest attainable two-sided p is 0.25); 5 + 4 = 9 baseline, 6 + 3 = 9 advanced. The hard case S10: no arm believed the docstring — false safes 0, the uploads verdict right in every delivered record — but four of its six runs cited the dead helper's file at the wrong line (`storage.py:12` for `avatar_key`). The verifier handed it back and the advanced arm delivered 3/3 (`traces/advanced/S10-s2.jsonl`, `S10-s3` also a missing `purge_closed_accounts` entry point); the baseline hit the same citation at render and died twice, delivering 1/3. Its remaining F1 gap is store naming (`uploads/avatars` vs the manifest's `upload`), the S04 artefact again | A tie on the mean, movement on the floor: delivery 5/9 → 6/9 on test, 25/30 → 27/30 overall. What the split revealed: every one of the sweep's eight failures is the render-time citation rule, and on S08 the verifier's `ast`-statement leniency accepted what the renderer refused — all three advanced runs died on a rule its own loop implements differently (`traces/failures/INDEX.md`, HOT_TAKE.md). Fixed after the sweep — ff8bfea makes the render check read the statement span as the verifier does — and the numbers above are the pre-fix system's, kept as measured: both live test slots were spent and a post-fix re-sweep is a different system |
