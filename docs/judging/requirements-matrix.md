# Requirements matrix

Every requirement the submission is scored against, extracted page by page from `docs/problem/problem-statement.txt` (the official statement, which wins over anything internal) and section by section from `AGENTS.md` (this project's own stricter rules). One row per requirement.

Read with `.vault/adr/0002-gdpr-inventory-erasure-check.md` (what we are building), `.vault/adr/0003-runtime-and-api-decisions.md` (model, API surface, record/replay), `docs/spec/00-contract.md` (the interface contract: layout, tools, budgets, feedback object, trace lines, scoring, CLI), `evals/CASES.md` (the eval design) and the `Makefile` (the commands). Status is as of 2026-08-28, hour ~4 of 75: the repo holds conventions, the decision log (ADR 0001–0003), the interface contract (`docs/spec/00-contract.md`), the research corpus (`docs/research/`), the case list and Makefile stubs. No fixture, harness, baseline or solution code exists yet: the gap between designed and built is what most `planned` rows mean. Rows read `at risk` where a decision is unresolved, not where work is merely unstarted.

Column meanings:

- **Satisfied by** — the repo path, command or artifact that carries the requirement. Paths that do not exist yet are the committed target, consistent with ADR 0002 and CASES.md.
- **Built in phase** — fixtures · harness · baseline · advanced · evidence · video.
- **How we prove it at submission** — what a judge (or we, on the final checklist) actually runs or opens to confirm the row.

## Qualification-gate risks

AGENTS.md §Competition facts: "the project must run and verify from a clean environment, with intact agent traces. Unreproducible scores zero." These are the five ways the score goes to zero regardless of the work.

| Risk | What it looks like on the day | Mitigation | The check that catches it | Exists? |
|---|---|---|---|---|
| Clean-env failure | Judge clones, runs `make setup`, and something resolves differently (stale lockfile, missing Python, uv version drift, a path only valid on the author's machine) | `uv sync --locked` errors rather than silently relocking [S4]; Dockerfile as the second path; rehearse the clone on a fresh directory and inside Docker before submitting | `make setup && make smoke`, then `docker build -t hackathon . && docker run --rm hackathon make eval-replay` | targets exist, rehearsal not done |
| Missing or unreadable traces | `traces/` is empty, or holds only the last run, or the build trajectory was never rendered because it lives in `~/.claude/` | Write traces as a side effect of every run (not an opt-in flag); commit the rendered build HTML rather than the command that makes it; keep `traces/failures/` populated | Proposed `make check-traces`: assert non-empty `traces/baseline/`, `traces/advanced/`, `traces/failures/`, and that `traces/build-trajectory.html` exists and is newer than the last code commit | **no target yet** |
| Unreproducible numbers | README quotes a number no committed artifact produces, or `make eval-replay` prints something different from README | Every number is generated by `make report` from `results/metrics.json`; README numbers are pasted from that output, never typed | Proposed `make verify-docs`: re-run `make report` and diff its table against the README block | **no target yet**; the replay layer it depends on is designed (ADR 0003 §6) and unbuilt |
| Secrets in history | An API key in a commit, even one later reverted | `.env` gitignored from commit one; `.env.example` holds names only; no key ever pasted into a file | `gitleaks detect --source . --log-opts="--all"` over full history [S3], run before the final push | **no target yet** (G-04) |
| Proprietary or private data | A client name, an internal path, a real personal record in a fixture | ADR 0002 keeps the lived incident anonymous; fixtures are generated schemas with no records; real repos are OSS at pinned SHAs | Proposed `make check-clean`: grep the tree and the git history for the forbidden name list and for anything matching an email or key pattern in fixtures | **no target yet** |

Assumption: the three proposed targets (`check-traces`, `verify-docs`, `check-clean`) are cheap enough to write on Sunday during the evidence phase and are worth more than one more advanced iteration, because each of them protects the whole score rather than part of it. They sit alongside the two the contract already requires and the Makefile does not have: `fixtures` and `run CASE=`.

## Designed but not yet built

Not gaps. These are decisions that exist in writing and are waiting on code, which is a different Saturday from an undecided one.

- **Replay layer** — designed in ADR 0003 §6: every request hashed (canonical JSON of model, system, tools, messages, output_config, thinking), the response committed under `evals/cache/`, `make eval-replay` running cache-only and failing loudly on a miss. The contract adds the path, the `--mode live|replay` flag and the `"mode"` field on `run_start`. Not yet implemented in `art30/llm.py`.
- **Trace schema** — contract §Trace contract fixes the four line types, every field AGENTS.md §Trace rules asks for, and the path `traces/<arm>/<case>-s<seed>.jsonl`. Written by `art30/trace.py`. No validator asserts the `call_id` pairing yet, and `run_start` carries no instruction hash.
- **Shared instruction text** — `art30/prompts/system.md` plus `art30/prompts/taxonomy.md`, byte-identical across arms (ADR 0003 §4, contract §Repository layout).
- **Human gate** — contract §Run phases 3: harness-driven, never model-initiated, `--approve ask` prompts and `--approve auto` records `by: "simulated"`, both written to the trace as a `checkpoint` line with the risk rating. REPRODUCE.md still has to state that difference in writing.
- **Provenance and cost accounting** — `SOURCE.md` per vendored tree (contract §Repository layout); per-step `usage` split into input, cache read, cache write and output, priced at contract §API configuration. Both specified; the README sentence about the baseline's retries being billed in is not written.
- **Makefile** — the contract requires ten targets and seven exist. `fixtures` (ADR 0003 §9, must produce a clean `git diff`) and `run CASE=` (the shot the video opens the execution segment with, `docs/demo-script.md` 0:10–0:25) are missing.

## Requirements the current plan does not yet address

Blunt list, eight items. Each is a decision nobody has made, not work that is merely unstarted.

**G-01 — no evidence of improvement over the way the task is handled today, and "human time per task" exists only for real repos.** PDF p.1 asks for "clear evidence that your solution improves the way the task is handled today". Today's handling is the manual process, PDF p.2 shape 04, which in this project is the hand-labelling protocol. CASES.md defines human time as the labelling minutes under that protocol, and the protocol runs on R01–R05 only. Synthetic cases have no human-time number, and neither arm has one distinct from the other, because both are unattended. Either the row measures the manual process against the tool and the README says so plainly, or it is replaced under the E8 "design your own rubric" clause. One decision covering Q6, E7 and X07.

**G-02 — the build trajectory lives outside the repo.** `make traces` runs `uvx claude-code-log@latest ~/.claude/projects/-Users-tun-Documents-micro1-hackathon` [S1]. On a judge's machine that path does not exist, and `@latest` is unpinned and needs network. The deliverable is the rendered HTML, so it must be committed; the target should be documented as author-only, and the version pinned (1.5.0 at time of writing [S1]) so the render is repeatable.

**G-03 — "what a good result looks like" is not written down.** PDF p.4 requires it before the evaluation runs. CASES.md defines the metric precisely and never states the target. Needs one line, committed before the first baseline run on Saturday: what F1 on dev, what F1 on test, false safe zero, and what would make the artifact unsignable regardless of F1.

**G-04 — no secret-scan target.** X20 requires gitleaks over full history before the final push [S3]; it is not in the Makefile, not in the Dockerfile, and not on the checkpoint table in STATUS.md. A manual "remember to run it" at hour 70 is how this gets missed.

**G-05 — the verifier has no tests.** It is the load-bearing claim of the whole project ("deterministic code the model cannot bypass", ADR 0002), and it is now four modules plus YAML rule sets (contract §Repository layout), which is more surface, not less. `pytest` is a dev dependency with zero tests. A verifier bug that fabricates a path is a false safe the eval cannot distinguish from a model error. Unit tests over hand-written call graphs, committed before the first advanced run.

**G-06 — the statistics don't match the metric.** `README.md:32` promises "paired per-task differences, exact McNemar". McNemar needs a binary per-case outcome; the primary metric in `evals/CASES.md` §Primary metric is mean F1, which is continuous. Either the significance test runs on the `pass` row (binary, and then say so) or the F1 comparison uses a paired test appropriate to it. As written the two sentences contradict each other.

**G-07 — `evals/tasks/` is a leftover from ADR 0001. [DONE 2026-08-28: directory removed, ADR 0001 superseded in part.]** ADR 0001 committed to "evals live as task files under `evals/tasks/`"; the contract's §Repository layout puts everything under `evals/fixtures/` with manifests and no `evals/tasks/`, and the contract wins until an ADR says otherwise. The directory holds a `.gitkeep` and nothing else. Housekeeping, not a decision: delete the directory and add a superseding line to ADR 0001 so the tree matches the spec.

**G-08 — LLM-as-judge is specified but unused.** AGENTS.md line 43 describes tolerance bands, order-swapping and an "Unknown" option for a judge model; NON-GOALS bans one from the primary metric; the current design has no free-text scoring at all. Either name the place it is used (the record's prose quality, for instance, scored once at the end) or drop the rule so a judge does not go looking for it.
