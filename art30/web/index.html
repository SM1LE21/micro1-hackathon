    About

    Who has this problem?

    The technical founder of a small EU SaaS, on the day somebody asks for the record of processing: a co-founder running diligence, a customer's lawyer, a supervisory authority. The document was written by hand months ago and the code has moved since. Nobody re-reads a spreadsheet against models.py every sprint.

    What bottleneck makes it worth solving?

    Writing the document is not the hard part. Knowing whether it is still true is. Drift between the document and the system is the failure. Reading the code by hand is the current fix, and it costs, per repository, the minutes the labelling protocol in evals/CASES.md measures.

    Does the agent solve it well?

    The agent reads the repository with three read-only tools and submits through a fourth. Every claim it submits is re-checked by a deterministic verifier on stdlib ast, which answers one structural question per store: does a static call path run from the erasure entry point to a deletion primitive for that store. The verifier hands back the struck claim, the reason and the line, as a tool result the model has to answer. An unresolvable call renders unverified rather than a guess in either direction, and a human gate fires before the record renders.

    Can another person reproduce it?

    make setup && make smoke && make eval-replay regenerates results/metrics.json from recorded API responses with no key, and ends in git diff --exit-code against the committed file.

    What this page is

    ADR 0007: "The CLI is the only thing that runs the agent loop, the verifier and the renderer." This page is the third surface, "a stdlib http.server on 127.0.0.1 that spawns art30 scan as a subprocess", tails the trace and exchanges the human gate through two files. It re-implements none of the three.
