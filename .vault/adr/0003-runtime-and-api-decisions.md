# ADR 0003 — Runtime and API decisions for both arms

status: accepted
date: 2026-08-28

## Decision

1. **Model.** Both arms run `claude-opus-5`, adaptive thinking with `display: "summarized"` (so the trace carries a reasoning summary per step), `output_config.effort: "high"`, `max_tokens` 16000. Overridable by environment variable for cost experiments; the reported numbers are Opus 5.
2. **No temperature, no seed.** The Messages API for this model family rejects `temperature`/`top_p`/`top_k` (400) and has no seed parameter. The "5-attempt retry with temperature ramp" in the original plan is replaced by five `submit_record` attempts per run in *both* arms at fixed settings. "Seeds" are harness-level only (case order, run labels). The three runs per arm measure sampling variance; REPRODUCE.md says so.
3. **Manual tool loop**, not the SDK tool runner, the Claude Agent SDK, or Managed Agents. Reasons: one JSONL line per step with usage and cost, record/replay keyed on the exact request, hard step budgets, no beta dependency in the reproduction path.
4. **Identical prompt and identical tool schemas across arms.** The system prompt (`art30/prompts/system.md`) and the four tools (`list_tree`, `read_file`, `grep`, `submit_record`) are byte-identical in both arms. The arms differ only in what the `submit_record` handler does (baseline: schema validation; advanced: schema validation + deterministic verifier + completeness guard) and in the human gate the advanced arm runs before rendering. The baseline is therefore exactly "a good SKILL.md with basic tools".
5. **No server-side refusal fallbacks.** A refusal is recorded as a run failure (`stop_reason: refusal`) and counted in `failure`. Silently re-routing to another model mid-run would contaminate the measurement.
6. **Record/replay.** Every request is hashed (canonical JSON of model, system, tools, messages, output_config, thinking); the response is stored under `evals/cache/` and committed. `make eval-replay` runs with the cache only and fails loudly on a miss. Deterministic tools plus committed fixtures make replay exact.
7. **Dependencies.** Runtime: `anthropic` (1.x), `pyyaml`, `jsonschema`. Dev: `pytest`. Verifier on stdlib `ast`. No CLI or TUI framework; `argparse` and plain stdout.
8. **Surface.** Package and CLI name `art30`. CLI only. The record renders to Markdown (canonical) and a static HTML page (for the video); no DOCX/PDF.
9. **Fixtures are committed**, generated by `evals/fixtures/gen.py` from YAML specs; `make fixtures` must produce a clean `git diff`.

## Context

The claude-api reference (cached 2026-06-24) records that sampling parameters are removed on Claude Opus 5 / Sonnet 5 / Opus 4.7+ and that `budget_tokens` is gone in favour of adaptive thinking and `effort`. AGENTS.md was written before those facts were checked. The spec verification pass re-checks these against live documentation; if any turn out wrong, this ADR is amended, not silently ignored.

The identical-prompt decision follows from Q1's framing question ("what is the difference between this product and a skill?"): the difference under test must be the closed loop and nothing else.

## Options considered

- SDK tool runner with per-turn hooks — would work, but the replay layer and per-step trace are easier to reason about when the loop is ours; beta surface avoided in the reproduction path.
- Structured outputs via `output_config.format` instead of a `submit_record` tool — two mechanisms for one job; the tool gives a natural retry channel for feedback.
- Different prompts per arm (advanced prompt explains the verifier) — muddies attribution. The verifier's feedback messages carry the explanation instead.
- Server-side fallbacks (the reference recommends them by default) — rejected for measurement integrity; noted for the user.
- `rich`/`typer` for the CLI — removes little code, adds a dependency to the clean-environment path.

## Consequences

- `results/` numbers are tied to `claude-opus-5`; a model change is a new changelog row, never a silent swap.
- The trace's `reasoning` field is a summary, not raw chain of thought; README says so.
- Cost per task is computed from `usage` at Opus 5 list prices (input $5, output $25 per MTok; cache write 1.25×, cache read 0.1×) and reported per run.
- Reopened by: live documentation contradicting item 2; replay misses caused by non-deterministic tool output (would mean a fixture is not frozen).
