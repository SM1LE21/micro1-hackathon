# ADR 0008 — Three brains behind one core, and one settings layer for every surface

status: accepted
date: 2026-08-30

## Decision

1. **Brains.** `art30 scan --brain api|claude|codex`. `api` is the loop as built (`art30/loop.py`, the Messages API, exact record/replay). `claude` runs `claude -p` as a subprocess on the user's own Claude login; `codex` runs `codex exec --json` on the user's own ChatGPT login. Both local brains keep the arms exactly as they are: `submit_record` is served to the CLI as an MCP stdio tool (`art30/brains/mcp_server.py`, stdlib JSON-RPC) whose handler *is* `baseline/arm.py` or `advanced/arm.py`, so a rejected claim goes back to the model as a tool error with the same strings; the human gate runs in our process after the CLI exits; the record is finalised and rendered by the same code. The CLIs' event streams are converted line by line into the trace contract (`request_hash` is null for local brains; `run_start` carries `brain`, `brain_model` and `cost_source`).
2. **Isolation.** Claude: `--append-system-prompt-file` (our instruction text), `--mcp-config` + `--strict-mcp-config` (only our server), `--allowedTools Read,Grep,Glob,mcp__art30__submit_record`, `--disallowedTools Bash,Edit,Write,MultiEdit,NotebookEdit,WebFetch,WebSearch,Agent,Task` (the repository is never executed), `--setting-sources project` and `--disable-slash-commands` (the user's `~/.claude` hooks, memory and skills stay out), `--max-turns`, `--no-session-persistence`, `--model` when set. Codex: `-s read-only --skip-git-repo-check -C <repo> --json`, MCP through `-c mcp_servers.art30.*`, `-m` when set. Codex's read-only sandbox blocks writes and network but not running the repository's code; the instruction text forbids it and the docs say so.
3. **Cost.** Local brains have no dollar ceiling; turns (`--max-turns`, default 60) and the existing tool-call and submit budgets bound a run. Cost per task is reported as an **estimate at API list prices** from the tokens the CLI reports (Claude also reports its own `total_cost_usd`; both are shown, labelled `cost_source: cli_estimate`); Codex tokens are priced only when a price for the model is configured (`codex_prices`), else the row reads "tokens: n" and "n/a". The API brain's measured cost stays the measured number.
4. **Eval.** Sweeps may run on any brain; the README table names the brain. Reproducibility per brain: `api` replays recorded responses through the loop; local brains commit every trace, every submitted record and every verifier feedback (`submissions.jsonl`), and `make eval-replay` **re-runs the deterministic verifier over every recorded submission and re-scores every record**, which must reproduce `results/metrics.json` byte for byte. What no brain can do is regenerate model outputs. The author's stated preference is to spend no API credits: the scored sweeps run on `claude`, with an optional small `api` check.
5. **Settings.** One loader (`art30/settings.py`), used by the CLI, the harness and the website: defaults → `~/.config/art30/config.toml` → `<project>/art30.toml` → `.env` (secrets only) → process env → CLI flags. Keys: `brain`, `model` (api), `claude_model`, `codex_model`, `effort`, `max_tokens`, `max_turns`, `tool_budget`, `submit_budget`, `max_usd` (api only), `gate_timeout`, `approve`, `concurrency`, `codex_prices`; env names `ART30_<KEY>`. `art30 config list|get|set|unset|path` on the CLI; a Settings view on the website (`GET/POST /api/settings`); the API key is written to `.env` by either surface and is never read back — presence only. The harness pins model, effort and budgets per cell, so a user's settings never leak into a sweep; `provenance.config` records what ran.
6. **User note** shown wherever a local brain is selected: "Local brains run the `claude` / `codex` command already installed and logged in on this machine. art30 never stores or asks for those credentials; if the CLI is not logged in, the run fails with the CLI's own login error. Anthropic does not allow third parties to offer claude.ai login or rate limits inside their products; this tool does not — it runs your own CLI on your own machine." Branding: "Claude (your login)", never "Claude Code".

## Context

The author wants to spend no API credits, has both CLIs logged in, and wants the website, the CLI and the skill to share one configuration. Probed 2026-08-30 on the build machine: `claude -p --output-format stream-json` reports per-message `usage` and a final `total_cost_usd` (client-side estimate); `codex exec --json` reports `turn.completed.usage` with input, cached, output and reasoning tokens. Anthropic's Agent SDK page: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products" — this tool offers neither; it invokes the user's own CLI, as a skill does.

## Options considered

- The Claude Agent SDK as a Python dependency — the same CLI underneath, one more package in the judge's install, and the terms note names it explicitly; the subprocess keeps the dependency list unchanged.
- Advisory verification (the model runs `verify.py` through Bash) — loses the gate and requires Bash, which allows executing the repository. The MCP tool keeps enforcement and removes Bash.
- Keeping the eval API-only — reproducible bit for bit, but the author's budget decision is to use the subscription; the re-verify replay is the honest substitute.

## Consequences

- `art30/config.py` changes again before any recording (ADR 0006 addendum): `brain`, `brain_model`, `max_turns`, and `load()` reading through the settings layer. The API brain's request bytes are unchanged: same model, effort, `max_tokens`, prompts, tools; the step-1 hash test pins it.
- Subscription plans have rolling usage windows; a sweep may stall mid-way. The harness records windows per arm; a stalled sweep is noted, never hidden.
- Local-brain runs are not replayable through the loop; the website labels them "play back" (the saved trace), not "replay".
- The core freeze (Sunday 19:30 UTC) covers `art30/loop.py`, `llm.py`, `tools.py`, the prompts, the schema and both arms. `art30/brains/`, `art30/settings.py`, `art30/web/` and the harness freeze Monday 09:00 UTC.
